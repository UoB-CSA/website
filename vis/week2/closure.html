How It Works & The Reasoning Behind It

In the program, the main thread creates a 2D slice of pixel luminances. Before passing this data to the worker goroutines, it wraps the slice in a closure using makeImmutableMatrix.

  • How the Closure Works: The function makeImmutableMatrix(matrix [][]uint8) returns an anonymous function: func(y, x int) uint8. This anonymous function "closes over" or captures the matrix variable from its surrounding scope. Even after the outer function finishes executing, the returned anonymous function retains a reference to the specific matrix instance it was created with. When a worker calls data(y, x), the closure dives into its captured scope, retrieves matrix[y][x], and returns the uint8 value.
  • Reasoning 1: Enforced Immutability (Thread Safety): Go slices are reference types. If you pass a [][]uint8 directly into multiple concurrent worker goroutines, there is nothing stopping a rogue worker from accidentally writing to the slice (e.g., matrix[y][x] = 0). By passing a function that only returns a value, you physically remove the ability to write to the underlying array. It creates a strict read-only API.
  • Reasoning 2: Abstraction: The median filter algorithm logic shouldn't need to know the underlying memory layout of the image data. By asking for a func(y, x int) uint8, the filter logic is decoupled from the storage structure. If you later decided to store the image as a 1D slice or generate pixels procedurally, you would only have to change the closure, not the complex sorting math inside the workers.
